## Findings

### Blocker
1. legion/vendbuy.go: the whole file was rewritten from CRLF to LF (git diff: 1353 lines changed; the real change is 1 line at the
   `b.vend.Sold += amt` spot, vendbuy.go:310). It conflicts with main now (merge conflict in legion/vendbuy.go; dynamic-pricing touched the
   file) and a resolution by "take theirs" would silently undo main's vendbuy.go changes. Fix: reset the file to main's bytes and add the
   single `noteFarmerSale(b, item, amt)` line keeping CRLF. I did exactly that in the scratch tree (diff against main: +1 line) and
   everything else passed, so this is the only thing between the branch and a merge. The fixed commit needs a new review of that
   one-line diff.

### Major (fix before `farmer_orders_on` is switched on; they do not harm live play while the flags are off)
2. farmers.go `noteFarmerSale`: the supplied count is filed under `meBand(b.BaseLvOr())`, the level of the MERCHANT character that is
   logged in, and it counts every item the merchant sells (also the "spare gear" parcels, parcel.go:200), not only what the hunter farmed
   for an order. The need side of the metric is keyed by the band of the bots that are short, so by-band coverage (marketmetrics.go,
   design 113-117) will be wrong and supply inflated. Right feed: count only items on the farmer's current or recent order (or in the
   engine's wanted set), keyed by the band the engine listed the item for, not the merchant's level.
3. Metric hole, Constitution 3.2: `noteMMFarmerHours` is never called, so `farmer_hours` stays 0 and `deaths_per_hour` stays null while
   `deaths` do count. The meter is blind for the number that judges farmer safety. The null is honest (mmNum ok=false) and with the flags
   off there are no farmers, so it is not a merge blocker, but it must be fixed before farmers go on, and the switch-on must not happen
   while the meter is blind (3.10). Right feed: the online time of roster accounts' sessions, added at session end in the bot's run loop
   (bot.go near the session teardown that releases `onlineSlots`, about bot.go:1545) as `time.Since(sessionStart).Hours()` for
   `farmerMember` bots. Hunter and merchant sessions both count (the farmer is online either way); if the denominator should be hunter-only,
   count only `charRole()=="main"` and say so in the metric's doc line.

### Minor
4. farmers.go farmerDecide "busy": a farmer that already holds an ordinary opportunity goal declines "busy", which counts as a decline
   and sets the 60 min `farmerLastAt` gap, so a farmer that mostly lives on its own goals can be locked out for hours and the decline
   stats fill with "busy". Better: do not count or gap a "busy" non-decision.
5. Decision gap and item cooldown are not persisted. Acceptable: the live order is persisted and reloaded (loadFarmerLocked, tested by
   TestFarmerOrderSurvivesRestart), so a restart cannot double-start an order; after a restart a farmer may re-roll one decision and take
   the same item inside 6 h once. Bounded and harmless.
6. `farmerCountersSnapshot` is dead code (no caller) and the comment "a dashboard read writes pending changes first" is not true yet;
   nothing reads data/farmer_orders.json in this tree. Wire it or drop the claim.
7. `migrateFarmerCounts`: idempotent in the normal case (rename to `.migrated` after adding; metrics load adds with `+=`, so order against
   loadMarketMetrics is safe). If the rename fails (for example a `.migrated` already exists on Windows) the totals would be added again
   on the next start. Never deployed, low risk; remove the file when the rename fails.
8. mail.go:312 `farmerNoteParcel` runs at the send, before the server confirms; a failed send still forces one merchant session. Harmless.

## Verified (no finding)
- Flags off, or a bot not on the roster: no behaviour or cost change. Every hook gates first: `farmerOn`/`farmerMember` read `tune()` and
  return before any lock when the flag is off (`farmerRoster`). With `farmer_roster_on` true a non-roster bot pays one `farmerMu` lock
  plus a map lookup on a pickup ack, a death and a vendor sale (the roster is re-read from disk only every 5 min, under the lock); that
  is small, and the lock order is consistent (b.mu -> farmerMu -> mm; nothing holds farmerMu and then takes b.mu; opps is taken after
  b.mu as in existing code). TestFarmerFlagsOffNothingChanges covers off and roster-only.
- Constitution 2.7: the engine's order is advice. `farmerFirstFit` takes the first of at most 3 ranked items that is off cooldown, has a
  `fitFarms` map and passes `soloMapOK`; min level 15 (`meMinLv`), EC39 gear gate decline, acceptance 0.5+0.5*greed, start delay 0-15
  min, life 90-150 min, 6 h item cooldown; every decline goes through `noteMMFarmerDecline` with its reason and an event line. A live
  order re-checks its map on every call and is dropped with a recorded "unsafe map".
- Metrics are canonical: all counts go through noteMM*; farmers.go keeps only `looted`, per-account deaths and live orders (no second
  counter set); `farmerMMTotals` reads the metrics for the file.
- data/farmer_orders.json: written to `.tmp` then renamed; reloaded on first use (expired orders skipped); saved at once on an order
  change and at most once a minute otherwise.
- pickChar (persona.go:142): after the restored-party, pin, single-char, brewer and guild-leader rules, so those win; non-farmers get nil
  and fall through unchanged. 70/30 hunter/merchant, parcel flag consumed once. `bot.go:1556` is the only caller, once per session, and
  the session loop plays one character per account, so the one-character-per-account assumption holds.
- mail.go hook cannot misfire for non-farmers: it needs roster membership and a recipient that is the account's own "vendor" character;
  the only code that mails an account's own vendor is parcel.go (hunter to shop).
- EC47: true for a farmer, with a qualification. A gear-gated farmer posts the failing piece through the shared `econWant` ("for my
  build"), but only when the piece is trade/drop only (economy.go, `pc.NPC == 0` and source trade or drop); an NPC-sold piece posts no
  want and is bought through the shared trip path, where `gearFromShop`/`browseShops` (town.go:496-525, vendbuy.go) take a player shop
  first when one sells it for no more than the NPC. No farmer-specific buying code exists; the farmers.go comment overstates "posts" for
  NPC-sold pieces.
- The gear-gate decline (EC39) records "gear gate" and the farmer keeps its normal routine, which is EC39-gated anyway.

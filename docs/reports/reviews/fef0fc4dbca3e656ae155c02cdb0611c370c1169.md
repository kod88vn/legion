## Verification of the six fixes

1. interestedBuyers floor (pricedyn.go 89-114): FIXED. The signature takes the seller's floor and the loop skips a buyer
   with `W < floor` (was `W == 0`). Tests: with the fix, TestThinMarketBrokeBuyerDoesNotCollapse and
   TestThinMarketSolventBuyerPulls pass (with the other 9 sim/want tests, 11/11). In a scratch copy with the line reverted
   to `W == 0`, TestThinMarketBrokeBuyerDoesNotCollapse FAILS and the solvent test still passes (so the pair separates the
   two cases: the broke buyer must not move the price, a 600z buyer must pull it down but not under the floor).
2. dynNeed gone: FIXED. `grep dynNeed` finds nothing; the field is removed from Bot (bot.go). wantBid is pure (writes
   nothing); the new `wantNeed(id)` returns 0 with the flag off, `buildNeed(id)` on. `Want.Need` (json:"-") is set at
   all 16 Want constructors in the repo (grep `Want{`: alchemy.go 2, cards.go 3, chatintent.go 1, economy.go 4,
   guildpool.go 1, guildstock.go 1, huntfit.go 1, refine.go 1, vendbuy.go 2). The brief says 19; I count 16 bot-want
   constructors plus the `map[string]*Want{}` initializer and the separate `humanWant` type (not a Want, no price model).
   No constructor lacks Need. Copies (`c := *w` humanguildlead.go, the `[]Want` snapshot) copy Need along. The diff of
   the 16 edits is only the added `Need: b.wantNeed(...)` field, nothing else changed (read hunk by hunk). Sellers read
   `w.Need` (interestedBuyers, wantCap); `Need <= 0` falls back to dynWantNeed 0.6, which is also the flag-off value
   (Need is always 0 then), so no behaviour reads it off.
3. wantCap (pricedyn.go 225-240): FIXED. Uses the want's own Need (0.6 if unset), and `min(c, w.Each*11/10)` when
   Each > 0: a buyer never pays above its own posted bid x 1.1. Flag off still `w.Each*11/10`. Test present
   (wantbid_test.go, "wantCap ... never pays above the want's own posted bid").
4. Unknown supply neutral: FIXED. dynSupplyDemand maps supply -1 to demand, so scarcity = 1.0; used by both
   vendPriceDyn and askPriceDyn. TestUnknownSupplyIsNeutral covers it. Demand unknown still max(.,0).
5. Buyer reference without scarcity: sound. A buyer's willingness is its own valuation (purse x need); scarcity enters
   once, on the seller's ask, and Clear then pulls the ask toward the best interested buyer. Putting scarcity into priceOf
   as well would apply it twice, because the ask is built on priceOf. The removed `marketFactor` multiplication in
   priceOf is the flag-on guard against exactly that double count; no double counting remains. One residual: in a very
   scarce market buyers do not bid up, so sales then clear near the buyer's willingness rather than the scarce ask; that
   is the intended EC48 behaviour (the buyer's money and need decide), and tuning can revisit it. Not a defect.
6. Stale comments: FIXED. pricedyn.go header rewritten (want sites wired, Want.Need, no-scarcity-on-buyers note, floor
   rule); the "not wired yet" text is gone; the wantBid comment no longer says the need is kept on the bot; economy.go priceOf
   comment tidied into two lines.

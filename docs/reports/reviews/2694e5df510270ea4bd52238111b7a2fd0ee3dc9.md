## Findings

### major: Arrow of Wind never matches (huntfit.go:84)
`arrowElement` tests the prefix "Wind ". The item 1755 is named "Arrow of Wind" (AegisName Arrow_Of_Wind). Wind arrows
are treated as plain. Name-prefix mapping from memory was wrong for one of four elements. Fix: map by item id
(1751 Holy, 1752 Fire, 1754 Water, 1755 Wind, 1756 Earth, 1757 Ghost) or read `bonus bAtkEle` from the item script.

### major: Silver Arrow (Holy) and Immaterial Arrow (Ghost) are not mapped, and elemMul has no Holy or Ghost rows (huntfit.go:80-92, aoe.go:52)
The Payon case in b1794773273mfy (Undead in Payon Cave) is not fixed in practice. Fire Arrows (1752) are sold only
in `alb2trea` Tool Dealer, `ein_in01` Tool Dealer and `lhz_in03` Arrow Merchant. No Payon shop lists a Fire Arrow.
Payon shops list only plain Arrow and Silver Arrow (1751, Buy 5; `payon_in02` Tool Dealer#pay2, `payon_in01` Weapon
Dealer). Silver Arrow (Holy) is the arrow that fits Undead in Payon, and it is fit 1.0 here, so a Payon bot still
buys plain Arrows. Needs Holy>Undead / Holy>Demon in the table (and Ghost arrows only exist in the hidden
`Arrow_Archer` market shop, see next).

### minor: Crystal, Wind, Stone, Immaterial arrows are not buyable by bots
They exist only in the hidden marketshop `Arrow_Archer` (npc/re/merchants/Extended_Ammunition.txt:194), reached by
NPC dialogue, which `loadNPCs` (data.go, `kind == "shop"`) does not read. So `arrowChoice` can pick only Silver (if
mapped) or Fire, in the few towns above. The Water/Wind/Earth mappings are harmless but dead code until those shops
are reachable.

### major: Demihuman race bonuses never match (cards.go:~96, data.go:244)
Card scripts spell the race `RC_DemiHuman` (227 uses in db/re) and the code strips `RC_`, giving "DemiHuman". mob_db
spells it "Demihuman" (451 mobs, the largest named race). Lookup `race["DemiHuman"]` is always 0, so every Demihuman
card (Orc Skeleton and similar, Hydra is Brute... ) is valued zero on every map. Compare case-insensitively or
normalize one side. Related, minor: `RC_All` (310 uses) and `Ele_All` (192) are stored under "All" and never hit, so
the all-monster cards stay at the old fallback value 1; they should count as share 1.0 (or be left out on purpose,
with a comment).

### major: HP potion tier raises potion cost by up to 18x per HP, no cap and no flag (town.go:150-200, 1300)
Cost per HP healed: Red 0.18 z, Orange 0.40, Yellow 0.88, White 3.3. Old code deliberately fell back to Red because
of "~2x the HP per zeny" (batch 16). Now for a 9,700 HP bot only White passes the 3% test, and the survival minimum
`potMin` (25 at lv60+, 30 above 3,000 HP; town.go:79-95) is bought first with no 500z reserve
(`potBuyPlan` town.go:1093 keeps only arrowReserve 50). A lv80+ bot with 6,500z spends about 6,000z on 5 White
Potions; 25 White = 30,000z. Not a bankruptcy trap: `pickHPPotion` falls back to the strongest tier with 5 affordable,
the HP top-up keeps `wingSaveFloor`, and Red still comes when under about 550z. But a bot that restocks 25-30 potions
an hour at White price turns potion spend from ~300z/h into 30-36k z/h, which cuts the zeny/h metric (Constitution
3.2, PR07) for every lv80+ bot, and nothing compares that spend with income. The fix targets the right symptom (a
45 HP potion at 5,000 HP is useless), but the choice should be bounded, e.g. count the cost per HP, cap
potion spend at a share of recent zeny/h, or buy the White tier only for the survival minimum and Orange/Yellow for
the top-up. Step 2 in `pickHPPotion` also picks the strongest tier with 5 affordable even when it fails the 3% test;
at 2,000z it takes 8 Yellow (1,640 HP) where 25 Red gave 1,375 HP for 250z.

### major: behaviour change on by default, no `tuning.json` flag (town.go, ammo.go, cards.go)
reviewer rule 3: behaviour changes sit behind a flag that defaults off. Potion tier, arrow choice, ammo swap and card
valuation all change live behaviour for every bot with no switch. Ayla's OpenKore is not touched (Legion bots only),
so G13/G19 are not hit, but a flag lets a metric regression be reverted without a redeploy of code (G15-G17).

### minor: ammo swap and shopping use the current Goal map (huntfit.go:74-79)
`huntMap` returns `Goal.Map` even when the goal is a town or travel destination; shares are 0 there and fit falls to 1
(plain), so a bot standing in town with Fire Arrows loaded may swap to plain and back (5 s throttle, hysteresis 0.01
helps). Card value also changes with the map, so gear scoring can flip between maps. Low impact.

### minor: elemental arrow stock costs 5x per arrow
`ap` is now the elemental price (5z against 1z) and feeds `arrowsWanted`/`potBuyPlan`, so a 1,000-3,000 arrow
target costs 5-15k z instead of 1-3k z. Justified on a fit map (about 1.25x) but there is no check that the
gain beats the price, e.g. the threshold is only `fit > 1.01`.

### minor: tests (huntfit_test.go, potpick_test.go)
Tests would not fail on the data bugs above: they register id 1751 as "Fire Arrow" (real: Silver Arrow, Fire is
1752) and use race "Undead" only. Add a test that loads real `item_db_etc.yml` names for 1750-1757 (the `*Live`
tests pattern) and one Demihuman card. The potion tests do assert the Red-at-high-HP case and fail without the fix.

### Sound
Crit-for-casters change is correct (gearStyle returns "magic" for wizard, sage, priest bases; priest_battle and
sage_hindsight stay melee and keep crit). Mob.Race read is correct. No effect on Ayla's OpenKore, human characters,
or live data (G06, G11, G23 not touched).

verdict: do not merge

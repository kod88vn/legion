## Findings
- minor, `tools/system/apartwake.py:86` (`moving = heading_to(...) or closing`): a state text of "going to <leader>" or
  "travel -> <leader map>" exempts a member from the wake with no time limit. A member stuck for an hour whose state
  still reads "going to Ayla" (blocked route) never wakes main; it is only in the queue (high after 10 minutes). Cap
  the exemption (for example 30 minutes apart even when heading to her) and test it.
- minor, `tools/system/bugq.py` `wake_reasons`: the 15-minute limit also applies to every non-apart partycheck item
  (`wants_wake` returns True for deaths, flips, long sitting), so a second real party emergency inside 15 minutes is
  delayed. This is the stated design; main reads the queue at the 30-minute report in any case.
- major for the Ayla cut-over, not for today (the switch is OFF): `tools/system/partycheck.py:151` and
  `tools/sentinel.py:415` find Ayla's party by `p.get("human") == "Ayla"`. An engine party has no human
  (`tools/system/aylawatch.py` documents this), so after the switch both silently see no party and file nothing, and
  the apart/wake logic added here never runs. `aylawatch.py` is the intended replacement but does not use
  `apartwake`. The fixer for the cut-over must either retire the party check of partycheck/sentinel on
  `engine_parties` or make them find the party by member name, and reuse `apartwake` in aylawatch.
- minor, `tools/sentinel.py:361-421`: `party_wake` keeps its last value between passes; harmless because it is only
  read when a `party` problem is in `found`.

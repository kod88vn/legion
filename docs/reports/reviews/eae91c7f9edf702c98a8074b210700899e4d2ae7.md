# Review of fix/watchdog eae91c7 (bugs b17947684039bz, b1794768403gyn, b1794768403bgi, b17947684036wq, b1794768403zrc)

Spec: Constitution 3.8, 3.9. The committed state passes its 23 tests (checked from `git archive` of the commit). The
worktree has uncommitted later edits (a lock and `watchdog-keep.cmd`, 28 tests, one failing); they are not part of this review.

## Answers to the five questions
1. Start under `stack.hold` (G21): no for the loop and containers. `watchdog.py:246-252` and `:265-278` gate every start on
   `stack.up` and not `stack.hold`; only the dashboard (DB06) is exempt, and `stackctl` makes up and hold exclusive.
   `hold` is read once per pass (`:180`), so a hold set mid-pass is honoured one pass late (minor).
2. G15: no. Containers use `docker start <name>` only (`:128`), a missing container is filed, never created, and no compose
   is called. rathena gap is 1 h (G16), kept in the state file (`:285`). A rathena restart by someone else is not counted (minor).
3. keeper.sh: harmless for the container (starting a running container is a no-op), but see major 2 for a second keeper.
4. Throttle: sound for containers (persisted, recorded on success or failure). It does not protect against live-but-stale
   processes, see major 2.
5. Report record: covers 3.8 (state of every agent and container) and half of 3.9 (agents alive, open and unassigned).
   Missing: whether the meter is reading, and the last deploy and whether it was kept (see major 3).

## Findings

### major
1. `watchdog.py:59-60,98-116`, bugq `cmd_watch` (bugq.py:351-362). The watchdog restarts the bug queue watch as a detached
   process whose output goes to `watchdog-restarts.log`. The watch exists to wake the main session by exiting, and on a wake it
   first runs `mark_woken` (clears `wake_seen`, sets `woke` on items). A detached copy therefore swallows the next wake
   (including urgent Ayla items) and the main session is never told. Whenever the main session's own watch dies or is stopped, the
   watchdog starts this copy. Fix: file the outage only for `bugq-watch`; never start it.
2. `watchdog.py:219-257`. Restart is triggered by a stale heartbeat alone, with no check that the old process is dead, and
   only the dispatcher has a single-instance guard. unwall writes its heartbeat once per full pass (`unwall.py:114`, 600 s
   limit) and a slow WSL map fetch can exceed it; keeper.sh has no lock, so a second keeper means two loops each counting
   strikes and each running `docker compose restart openkore-ayla` (AY03, G19/G20 risk). Every 10 minutes another copy of any stale-but-alive
   script piles up. Fix: a pid or lock check before starting (or kill/skip when the process exists), and refresh keeper and unwall
   beats inside their long steps.
3. `watchdog.py:312-313`, Constitution 3.9. The 30-minute record has no meter state (reading or not) and no last-deploy
   line (what it changed, kept or reverted). The summary the owner is to receive therefore cannot answer 3.9 by itself. Add both
   (from the meter file and the deploy log the dashboard already reads).

### minor
- Nothing pushes the record to the main session: the file is only read by the dashboard (`dashserve.py` alarm). If the watchdog
  itself dies there is no restarter and no queue item, only a dashboard alarm; 3.8 "a missing report is an alarm" is met only
  while someone looks.
- After `stackctl up` ends a hold, every idle script's heartbeat is stale, so one pass files an outage and restarts each of them at
  once (a burst of false outage items, a restart storm of 6 scripts). Consider a grace period after `stack.up` appears.
- `start_agent` hardcodes `Ubuntu-24.04` (`:110`) while docker uses `dashserve.WSL_DISTRO`.
- Restart throttle records the time even when the start failed, so a failed start waits 10 min (1 h for rathena); acceptable but undocumented.
- Tests do not cover the detached-watch wake swallow, a second keeper, or stale-but-alive processes.

Behaviour is on by default only once the owner starts `watchdog.py` (not auto-started); no `tuning.json` flag is needed for that.

verdict: do not merge

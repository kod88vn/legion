## Findings
- blocker: none.
- major: none.
- minor 1, tools/puppet/dispatch.py:466-475: `event_cursor` advances even when `names` is empty (first poll after a restart, an API
  blip, the party between disband and re-register), so a party member's death in that gap never wakes the helper. The helper
  still sees it by the idle/watchdog paths. Acceptable; a refinement would be to keep the cursor while the party is unknown.
- minor 2, tools/system/aylalog.py:426: `unknown-switch` is filed once per switch forever (`last` is persisted in
  aylalog.state.json). A different switch is a different key (`ayla:unknown-switch:<switch>`), so a new problem still files.
  What it hides: a known switch becoming frequent or starting to coincide with a real fault. `file()` writes the hit count only at
  filing time, so later hits are counted in `Filer.hits` (state file) but not shown on the queue item. The 40 new keys/hour cap
  still applies. Priority "low" is accepted by bugq (PRIO_W). Fine for console noise; a hits bump on the item would close it.
- minor 3, tests: the dispatch test does not cover the case "names filled, stranger's death with 'ayla' in the text" (code returns
  None). Tests do fail on the old code (bare word map; empty names returns death).

## Findings

### Major

1. legion_crier.txt:15 (and :16): `query_sql` returns -1 on failure (script_commands.txt: "number of rows or -1 on failure"), and -1 is true in an `if`. If the table `legion_notice` does not exist yet (the SQL file is not loaded by any compose step, it is a manual load into ro-db) or the DB errors, the NPC passes the condition with `.@id` = 0 and an empty `.@msg$` and announces an empty blue line every minute between 08:00 and 22:59. Fix: test `> 0` (`query_sql(...) > 0`), and state in the deploy note that the table is created before the map-server restart.
2. legion_crier.txt:16-17: the UPDATE result is not checked. If it fails (lock, privilege) the same row is announced again every minute until it works (a spam loop, visible to every player). Fix: `if (query_sql("UPDATE ...") > 0) announce ...` (announce only after the row is marked sent), or announce only when the update affected a row.
3. crier.py:57-58 and :135-136 against legion_crier.txt:14: two different clocks. The tool uses the host's local time (`time.localtime`); the NPC uses the game server's time. Right now the host is EST and the ro-rathena container is UTC (5 hours apart). The effective window is only the overlap (08:00-17:59 EST), and a notice written at 18:00-22:59 EST sits in the table until the NPC opens at 08:00 UTC and is announced hours later, stale (the item may be covered by then), and several waiting rows come out one a minute. The design says the window is the server's time window (section 5.2). Fix: pick one clock (the server's: use UTC in crier.py, or read the container's `date`), and have the tool refuse a row the NPC will not announce now; optionally add a `created_at` age limit in the NPC SELECT (for example ignore rows older than 2 hours and mark them sent).

### Minor

4. crier.py:71 (event template "this evening"): a notice can go out at 08:00 and the word "evening" is then false. Drop "this evening" or restrict the template to hours 17-22.
5. crier.py:149-152 (live path): the row is inserted first and the jsonl history is written after. If the jsonl write fails the cadence history misses a live notice. Write the history first or in a `finally`, or make the failure loud. Low risk.
6. crier.py:103: the slot rule refuses any item or place name that contains a digit or a period ("Prontera Field 02", "Old Card Album"), which the design example uses. This is the safe direction; the engine hand-off will need display names without digits. Note for the engine work.
7. legion_crier.txt: an empty `OnTimer` pass runs a query every 60 s all day even when the table is empty; negligible (indexed on `sent, id`).
8. The README or deploy note does not list the order for going live (load `legion_notice.sql` into ro-db, then map-server restart in the window, then the flag). Add it to the deploy brief; the table must exist first (see finding 1).

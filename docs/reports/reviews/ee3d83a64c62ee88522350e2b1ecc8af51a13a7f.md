## Major
- `legion/strategy.go:183`, `legion/fairgate.go:51`, `legion/ai.go:790,886`: the gate can leave a bot with no spot at all, and the retry does not help. Spot lists are chosen by the effective level (`powerLv()`: gear based, only lv-penalty, down to lv/2 for bad kit), but the gate's floor is `BaseLv - 15`. A bot whose power is well under its base level asks for a band that mostly holds monsters of about its power level, and needs half of them at or above base-15. Example, base 60 with power 43: floor 45, guide spots for level 43 (gef_fild10/03 orcs, moc_fild03, pay_dun02 ...) mostly hold monsters under 45. Same for base 70 / power 50 (floor 55). Both the guide list and the SpotsFor fallback come out empty, `chooseHuntingGround` sets idle "auto (nowhere reachable)" with `huntRetry` +1 min (ai.go:886-891), and a minute later it runs the same inputs and gets the same empty result. Nothing changes the answer except a gear or level change, so such a bot idles indefinitely, no kills and no exp, which is worse than 0 fair kills. The new retry (huntRetryDue) is correct but only re-runs a deterministic empty pick. I could not check it against live map data (no rathena db in this environment); the test only covers an artificial lv45 / gef_fild05 case. Fix: when the gated list is empty, fall back to the ungated list (or the best-share map) instead of idling, and/or measure the gate at the level used for the band. Add a test with power far below base.
  - Common classes affected: any class poorly geared at base level 45 and up (the mid-level range where guide bands run under the base-15 line); not low levels (floor under 1 below lv 16 passes everything).

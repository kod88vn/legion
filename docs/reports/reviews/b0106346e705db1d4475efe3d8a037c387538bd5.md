## Findings

### Major
1. `legion/ai.go:547` (b1794735066954-196): the diagnostic cannot fire for the reported symptom. The report is goal
   idle, set_by exactly `auto`. Only town.go:900 writes `Goal{Mode:"idle", Map: b.MapName, Set:"auto"}` (the end of
   "calling it a day"); every other auto idle carries `auto (nowhere reachable)`. The new line sits in the branch that
   needs `Goal.Map != b.MapName`, and an idle goal's Map is the bot's own map. So it never logs an idle-in-town bot,
   only far-goal drops. The bug would stay open with a probe blind to the report. Put a probe where an idle auto goal
   lives (for example an event after N minutes idle with sessionEnd, pinned, alwaysOnline, dealOpen and
   ShouldBeOnline in it).

### Minor
2. `legion/ai.go:547`: `b.event("info", ...)` is not inert. `event` also writes the text to the bot's diary
   (bot.go `remember`; the diary is capped at 300 entries, memory.go:199), which feeds the chat/mind briefs and
   `kafraLastFromDiary` (kafra.go:706). Rate: at most one per 120 s per stuck bot (lastPosAt is reset on a drop), so
   a bot looping through far goals adds up to 30 internal-looking lines an hour (state, route, path, via) and would
   evict real entries after about 10 h. It cannot cause chat (`chatterReact` ignores "info") and does not change
   behaviour (it only reads fields; the one RNG draw in chatterReact is the only side effect). Prefer an event kind
   the diary skips, or one line per bot per hour.
3. `tools/system/fieldcheck.py`: the commit rewrote the whole file with CRLF line endings (849 changed lines;
   `git diff --ignore-cr-at-eol` is 55 lines; the other files in the commit are LF). It runs, but it hides history
   and blame. Restore LF before merging.

  (ai.go:3209). The earlier fixer's note (bugq line 1560) says the same.
- A latent defect exists on that path: nothing re-picks a goal after that idle. `huntRetryDue` (ai.go:721) handles
  only `auto (nowhere reachable)`; the town.go:900 idle has no retry marker (the hole b1794735068469-692 fixed for
  the other idle). If `logoutSignal` does not end the session (ShouldBeOnline stays true because `pinned()`,
  `alwaysOnline()` or the guild-brewer flag became true after sessionEnd was computed at login, bot.go:1592; or a
  `dealOpen` hold of up to 15 min), the bot stands idle for good. I did not prove that any of these happened to the
  wolfgirl; it needs a live read of her sessionEnd, pin and ShouldBeOnline.
- The 120 s no-move watchdog loop (drop an auto far goal, re-pick a far goal) is real, but it cannot produce an
  "idle auto" snapshot; it fits only the travelling share, and stuckWatch (rally.go:758) already covers "trying to

So keeping the bug open is right, but the probe must target the idle goal (finding 1). This is not a fix for
b1794735066954-196 and must not be recorded as one.

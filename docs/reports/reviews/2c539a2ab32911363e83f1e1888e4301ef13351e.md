## The brief's points
1. Guard strength. The old guard re-ran 5 hard-coded suites with LEGION_TEST=1 and relied on the resolver
   (`common.refuse_live`) alone, so a test that opened a live file by its own path was never caught. The new guard
   re-runs every discovered suite and adds the audit hook in every Python process of the run. Mutation done in the
   scratch clone: a planted test writing `legion/data/probe.lock` fails with "G23 tripwire ... (open for write)" and
   the file is not created; a planted test reading untracked `legion/data/running.state` fails;
   `gatecheck.run_suites()` returns the suite as failed. Stronger than before. Not caught (also not by the old
   guard): a test that wraps the write in `except Exception`. The guard test is skipped only when
   `LEGION_GUARD_CHILD` is set, which the runner sets on every child; run alone it runs the runner. Acceptable.
2. Hook safety. Tracked config readable (tested); temp dirs fine; `LEGION\DATA`, `..` segments, relative paths after
   chdir, bytes paths, rename, remove, mkdir, makedirs, pathlib and shutil.copy all handled. Overhead: 30000 opens
   3.42 s without the hook, 3.50 s with it (about 2 percent); interpreter start-up 22 ms vs 23 ms. The full suite
   ran green under the hook, so no legitimate use is blocked. Bypasses are minor (below). Failure mode: if
   `sitecustomize.py` raises at import, Python prints one stderr line and the process runs WITHOUT the hook
   (verified): fail-open, only noisy.
3. Timeout and tree kill (Windows). `taskkill /F /T /PID <child pid>` of the unreaped child: verified that a
   grandchild died and an unrelated Python process survived. The PID cannot be reused before `p.wait()`. Output goes
   to temp files, so no pipe stall.
4. gatecheck with suites: a failing suite is returned by `run_suites()` and added to the failures as before.
   `--changed`: a change to testenv.py, common.py, runsuites.py or gatecheck.py runs every suite, and a git failure
   runs every suite. Unknown paths do NOT fall back to everything: see major 1.
5. gocheck.sh. No WSLENV; values travel in the command string through `printf %q`. A path with spaces, `$` and an
   apostrophe works. `G:/RO/...`, `G:\...` and `/g/RO/...` all become `/mnt/g/RO/...` (the old `${DIR//\//}` form
   dropped every slash: fixed). The HEAD check uses Windows git and prints at start and end. Gaps: minor 6 and 7.
6. `.gitattributes` `*.sh text eol=lf`: every `.sh` is already LF in the index (`git ls-files --eol` shows `i/lf`),
   so no renormalise commit is needed and no whole-file diffs appear after the merge. Existing CRLF working copies
   (autocrlf=true clones only) stay CRLF until re-checkout and are not shown as modified. The real checkouts have
   autocrlf=false and `w/lf`. Nothing depends on CRLF in `.sh`. Without the attribute an autocrlf clone fails
   `test_watchdog.test_keeper_script_writes_heartbeat` (seen on the scratch clone), so the change is right.
7. Lock message. The full run under the hook had no tripwire hits. Lock-touching tests (`deploy.lock`,
   `watchdog.lock`, `keeper.lock`, `aylawatch.lock`) all go through `C.dpath` or a temp `self.d`. Confirmed.

## Findings

### Major
1. `tools/system/runsuites.py` `select_for_changed`: `--changed` can silently skip suites.
   - A changed `legion/*.go` file is dropped (`continue`), yet `tests/dashboard/test_builds.py` parses
     `legion/builds.go`. `select_for_changed(["legion/builds.go"])` returns `['tests/system']` with no reason line, so
     only the core and `gocheck --fast` run.
   - A path that no suite names (a new module, `tools/system/tripwire/sitecustomize.py`) selects "core only"; the test
     `test_an_unmentioned_file_runs_the_core_only` locks that in. Selection is by file basename, so common names
     over-select and unique names under-select.
   - Fix: do not skip `.go` (select suites that mention the file, else everything); for any non-doc path that no
     suite mentions run everything (or print a loud WARNING). Skipping `docs/` and `*.md` is fine.
   - Not a blocker: it does not touch live play, and the full run is the gate per `docs/handover/testing.md`. Fix
     before `--changed` is used as a review shortcut.

### Minor
2. `tools/system/tripwire/sitecustomize.py` (last line): fail-open on an error in the hook or a shadowing
   `sitecustomize`. Add a canary: the runner first runs one child that tries to write the live folder and aborts
   the run if it is not refused.
3. Same file, bypasses: junction or symlink to the live folder and 8.3 short names (both verified to open and write
   successfully), sqlite (C-level open), `python -I` and `-S`, non-Python children; a test that swallows
   `Exception` hides the RuntimeError; listing a live folder is not blocked. `os.path.realpath` in `_norm` closes the
   first two cheaply.
4. `runsuites.py` `_tracked_live_files`: `git ls-files` quotes non-ASCII names, so such a tracked file would not be
   readable. Use `-z`.
5. `tests/system/test_runsuites.py` `test_run_bounded_kills_the_whole_tree` checks only elapsed time, not that the
   grandchild is gone (verified by hand that it is).
6. `tools/dev/gocheck.sh` `head_win` falls back to `none` when git cannot read the path (verified with an apostrophe
   in the path from Git Bash); then `none == none` and the HEAD-changed check silently does nothing. Working-tree
   edits during the run are not detected either (HEAD only).
7. `tools/dev/gocheck.sh`: each full run leaves `~/gocheck-last.XXXXXX.log` in the WSL home and never prunes (7
   present after my runs); the old fixed name overwrote itself. Keep the last N.
8. `tests/system/test_livedata_guard.py`: the planted-leak cases still test only the resolver; the audit hook is
   tested in test_runsuites. Say so in the docstring.

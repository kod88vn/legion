## 1. aylalog.py (ee521d6)
Correct and bounded: binary-safe tail with truncation/rotation handling, flood guards (20 writes a cycle, 40 new keys an
hour), one write per key per 10 min, single-instance lock via `take_lock`, `--dry-run` writes nothing. G23: the default log
path now goes through `C.refuse_live`; the tests build temp dirs (test_aylalog.py:147,175-176). It only files; it never
touches Ayla.
- minor, still on main: `Tracker.feed` emits a high `log-silent` event for any gap over 10 min in the timestamps, so a
  restart of Ayla's OpenKore (G19 allows 5 min; a longer outage is already an outage item) also files a log gap afterwards.
- minor: the meter check calls `GET /api/meter/neo` every 10 min with an 8 s timeout inside the loop; a hung API delays one
  poll but not other scripts. Acceptable.

## 3. restore-behaviour (aa02068)
`exchange_tiers_on` stays default off, so the exchange part changes nothing until the owner turns it on. The kin stage logic
(`exKinStage`, `exUrgent`) and `exchangePrefer` (tier, then nearest, then spare) are pure and tested. The duty-window and
kick-cool-down changes are always on and match GD02 and the kick rules (a kick binds only the kicked character; G06/G11 safe).
- minor, still on main: `guildstore.go` counts everything a leader or guild vendor stores (`noteGuildStored` uses all
  `storeCandidates`, before the storing succeeds) and never subtracts, so "guild stock in storage" on `/api/guild-stock` is an
  upper bound that only grows until restart. It is informational (documented), but a dashboard reader may trust it.
- minor: `dutyWindowOpen` mutates `b.fgoal` and takes `gduty` while `b.mu` is held; the order matches `guildBlockStatus` and no
  inverse order was found. Not run under `-race` here.

## 5. leadertalk.go (57475f0)
G18 clean: the lines are ordinary player talk (town run plan, "waiting for X at the kafra", "wb", "gl"). Human-led parties are
excluded in both the narrator (`p.Human != ""`) and `leaderHeard`, so Ayla speaks for herself. Once per decision, a 2 min
per-member-and-kind cooldown and an 8 s global gap bound the volume; `leader_talk_off` is the kill switch. Tests use seams
(no sleeps; hardened later by bb82db3). `r := p.Rally` is a value copy, so clearing `excluded/lastPos` does not touch shared state.
- minor, still on main: `partySaid` (map keyed by `*Bot`) is pruned only when that bot speaks again, so a bot that goes silent
  keeps up to 8 lines; bounded by the bot count.
- minor: `leaderHeard` is started with `go` for every bot that hears a party line (bot.go party-chat hook) but returns at once
  for everyone except the bot leader; cheap.

## 7. ayla-tell (cb5ccdc)
G05: `ayla.sh send()` strips CR/LF so one send is one console line, and `map` validates the name; there is no route to a bare
`ai`. G13: the owner's order goes through the helper agent. The dispatcher wakes the helper for open orders at most every 30 s
and closes unreported orders (`close_unreported`) so a failed call never loops. Tests use `AYLA_ORDERS`/`AYLA_ORDERS_LOG` temp paths.
- minor, still on main: `AYLA_ACT` now contains `rally`, `party`, `townrun`, `done` for every helper call, not only owner-order

- minor: order ids are `o` + MMDDHHMMSS + 2 hex digits (orders.py add), so two orders in the same second collide 1 in 256 and

  (G23); closed by commit 4b86339 (resolver).

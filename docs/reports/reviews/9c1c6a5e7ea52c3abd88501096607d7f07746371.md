- Review file only in the working tree: `git show HEAD:<path>` reads the tree, so it does not count. A forged file that is committed before HEAD does count (inherent, cannot be told apart).
  A review committed after the merge but before HEAD counts (correct).
- Verdict: last non-empty line only; `do not merge` refuses; anything else is `none`. Good.
- Time fallback: uses committer date (`--before`), `-1`, first-parent. A skewed or forged-late commit date only moves the base to an older commit (more merges checked, fails safe);

### major
M1. `deploy.py:gate_merges`/`merge_gate` (line ~203) and `batch`: HEAD is not required to be `main`, but the sync exemption reads the `main` ref. Reproduced: a feature branch with an
  unreviewed code commit, `git merge main` into it, check it out and run the gate on it: verdict `sync`, 0 offenders, so the feature commit would ship unreviewed. This is the
  old m4 of the e82955d2 review, still open. Needs an operator error (deploying from a non-main checkout), so it does not block. Fix: refuse unless `HEAD == refs/heads/main`
  (and read the chain from HEAD, not from the ref name).
M2. Non-merge commits are not gated at all. In the real range 3 code-touching direct commits sit on main: ed6517e (tools/deploy, the deploy gate itself, no review file),
  a63d9c5 and ae4c877 (dashboard, `legion/*.html`/dashboard code; owner-asked dashboard changes are allowed to be deployed at once under G17/DB03 but still Constitution 4.2).
  Fast-forwarded branches and rule/review commits behave the same. The gate therefore proves "every merge is reviewed", not "every shipped change is reviewed". Recommendation, as a
  follow-up (not a blocker, the gate strictly improves on today): in base..HEAD list first-parent non-merge commits that touch BUILD_PATHS, tools/deploy/ or legion/*.go and require each to be
  reachable from a reviewed second parent or to have its own `docs/reports/reviews/<sha>.md` with `verdict: merge`; review/rule/doc-only commits stay exempt by path.
  Until then the main session should treat direct code commits as needing an explicit review file by hand.

### minor

m2. `--image` mode records `sha=None` (`deploy.py` record call); the next base is again time-based. Record the image's build sha (label) when the image tag work in the earlier review M1 follow-up lands.
m3. `SYNC_SUBJECT` needs `main` directly followed by `into` or ` of X into`; the old "Merge main (fix/party-destination fd1f3da) into fix/party-stick" form is therefore an offender (old history only).
m4. The refusal text and docstring promise "no override"; there is none. Good. The test run is slow (17 tests, 20 s, real git); acceptable.

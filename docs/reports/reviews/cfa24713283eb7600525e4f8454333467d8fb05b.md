## Findings

### Major (guide not followable as written; no harm to live play, so not a merge blocker)
- M1 SETUP-NEW-MACHINE.md section 2: "Clone from the owner's own remote", but no remote exists. The guide must say how to
  move the repo itself: `git bundle create` from `G:\RO\legion` and `git clone` from the bundle, or copy the whole folder
  (including `.git`). Also say the bundle does not carry git-ignored files (section 4 covers them) and that `G:\RO` itself is
  not a repo (CLAUDE.md goes beside it).
- M2 Section 7 / 8: no concrete first-start command. It defers to STATUS "How to start", which is a plain
  `docker compose up -d`. On a fresh machine that starts `openkore-ayla`, `legion` and `legion-core` as well, contradicting
  section 8 items 3 and 8 ("Ayla stays held, nothing else starts") and the guide's own "never a plain up". Add the staged
  commands: `docker compose build rathena` first, then `up -d db`, then `up -d rathena`, and so on, with the first
  build of the `legion` image after `ro-rathena:20210107re` exists. Say which services stay down.
- M3 Section 5, fresh-DB route: "Load the tracked `seed.sql` into an empty database" has no command. The repo has it
  (`legion/README.md:111`: `docker exec -i ro-db mariadb -uragnarok -pragnarok ragnarok < legion/data/seed.sql`). Add it
  (use the env-var form of the dump and restore commands for consistency) and the order (after rAthena's first init created
  the schema, which needs rAthena to have started once).

### Minor
- m1 Section 1: no install steps for WSL2 (`wsl --install -d Ubuntu-24.04`), Docker Engine in WSL (how, and that
  `docker` must be usable without sudo), Python, Git Bash; only versions. The Go install is delegated to
  `docs/design/toolchain.md` (fine). Honest "not found in repo" notes exist for Docker; say Docker is needed before any
  step in section 5.
- m2 Dump commands: syntax is correct for `mariadb:11.4` (`mariadb-dump`, `mariadb`, env vars read inside the container,
  `--skip-ssl` accepted). Notes: `ro-db` must stay up while the writers stop (step 1 says "stop the engine services",
  say explicitly not `db`); rAthena tables are mostly MyISAM, so `--single-transaction` gives no consistency, which is
  fine only because the game is stopped (the guide already says so; say why); the dump holds no user grants (`dash_ro`
  is noted). Restoring as user `ragnarok` works because it owns the database.
- m3 Paths other than G: section 9 gives the `subst` route and the bug clusters; many scripts still hard-code `/mnt/g/RO`
  (filed). Acceptable as documented; `subst` is untested (said so). The guide should say WSL mounts any Windows drive
  letter, so a different letter is the failing case, and `subst` does not persist across reboot.
- m4 portcheck.py: `-h` exits 2 (the `SystemExit` catch swallows help's exit 0); exit code 2 should be for bad
  usage only. `check_tools` requires `wsl` on PATH, so the tool cannot be run from inside WSL. `tracked_files` falls back to
  a directory walk when git fails; a temp dir inside another git repo would scan that repo's list (not a live-data risk).
- m5 Section 10 row 1 says "Owner decision needed on rotation (G22)". That is stale: the owner decided fake-account
  passwords need no removal (see 6 below).

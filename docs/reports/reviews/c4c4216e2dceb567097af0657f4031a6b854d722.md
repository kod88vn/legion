## Findings

### Major (the page shows `missing`, not a wrong number; no harm to live play; align before the tab is useful)
1. Contract mismatch with the real engine API (legion/marketengine.go, `registerMarketEngine`, line ~886 and
   `MEResult`/`MEAllocation`). The fake engine (tests/dashboard/fake_engine.py:206-231) invents a different shape, so
   the tests prove the page against the fake, not against Go. Real `/api/market/engine`: `status` ("ok", "no_data" or
   "off"), `runs`, `last_run`, `farmers`, `caps` {per_item, per_map, ordered}, `ordered`, `unassigned`,
   `distribution` {by_item, by_map, max_item_share}, `needs` [MEGap], `orders` [MEOrder: farmer, item_id, item, map, mob,
   y_per_h, value, held, rank]. Field by field:
   - `caps`: matches as a dict (names per_item, per_map, ordered). Works.
   - `allocation` [{item_id, item, farmers, maps}] (marketview.py:185, 238): does not exist. "Farmers per item and map"
     and "Spread per item" show missing. Align: build it from `distribution.by_item`/`by_map` or from `orders` grouped by
     item_id (farmers = count, maps = by `map`), and read `needs[].farmers_on` and `drop_maps`.
   - `prices` (section 3): not produced by the engine (no price model on main; the dynamic-pricing branch is not
     merged). The Prices section always says "source not available" until that lands.
   - `broadcast.cadence` (marketview.py:320): not in the engine. The cadence lives in constants in
     tools/system/crier.py (`cadence_ok`, SAME_ITEM_S, server_hour). Section 4 cadence shows missing; align by having the
     crier or the engine publish its cadence, or read it from crier.py's exported constants.
   - `farmers.zeny_h` (marketview.py:266): real source is the feed's `zeny_per_hour` [{band, n, zph_mean}] (MEFeedZeny,
     marketengine.go:557). Same row fields; only the location differs. Read it from the feed object.
   - `flags` in the engine answer: not present; the view already falls back to tuning.json (works).
   - `missing` list: the engine answer has none; `MEFeed.missing` has. marketview.py:198 reads only the engine's, so the
     feed's `missing` and `status` are never shown. Read both.
   - Offline file stand-ins: the engine writes only `data/market_feed.json` (writeMarketFeed). `market_engine.json` and
     `farmer_orders.json` have no writer on main, so with the engine down the engine/orders sections have no file.
     Either the engine core should write them or the view should say so (it does say "source not available").
   - `/api/market/feed`: matches. `short` rows carry item_id, item, band, demand, listed, price (also kind, drop_maps,
     farmers_on); `t` is an RFC 3339 time (handled by `epoch`); `status`, `missing`, `server`, `glut`, `zeny_per_hour`,
     `guild` (only with ?guild=) are real. The `guild`/`guilds` block and `server` are not shown (not required).
   - When the flag is off the engine answers `{"status":"off","flag":...,"note":...}`; the view shows "engine says off"
     and the sections with missing items. Works.
2. Orders shape (marketview.py:226-248, fake_engine.py:226): expected `{orders:[{farmer, char, maps, until}], stats:
   {accepted, declined, declines}}`. The only real orders today are `orders` in `/api/market/engine`
   (farmer, item_id, item, map, mob, y_per_h, value, held, rank). `stats` and `until` exist nowhere on main yet. The
   farmer-orders branch must either serve `/api/market/orders` in that shape or the view must be changed to match.

### Minor
3. Crier format (marketview.py:313-314, 328): the crier writes `{t, at, kind, item, place, text, mode: "live"|"dry"}`
   (tools/system/crier.py:194). The view reads `t` and `text` (right) but `sent` does not exist: "N marked sent" will
   always read 0 and the column "not recorded". Align: treat `mode == "live"` as sent, and show `kind`/`place`. Also the
   file holds dry-run rows (default mode); they appear as notices and are not marked as dry.
4. Kite (marketview.py:252-262): the `/api/economy` `kite` block matches the real keys (`kite_steps`, `kite_deaths`,
   `counters_since`, `by_bot`; legion/economy.go:2017, kite.go:186). The offline fallback reads `kite_counters.json`;
   a core instance writes `kite_counters_core.json` (kite.go:155). The file keys (`steps`, `deaths`, `since`) match.
5. Facts block `engine.item_creamy_card`, `engine.item_creamy`, `engine.item_trap` (market-engine-facts.md) are typed
   copies of Go constants, with file:line sources, not read from the code; nothing tests that they agree with
   guildstock.go:36, teleport.go:19, kite.go:26 (they do today: 4040, 4040, 1065). A drift test would close DB11 for
   these three.
6. Some facts' line citations are off: the WalkSpeed facts cite mob_db.yml:901 and :76377 (those are the Creamy_Card drop
   lines; WalkSpeed is at ~877 and ~76352); values are right.
7. The page keeps the 30 s `setInterval` poll only while the tab is shown; fine. `ALLOWED_JS` contains "30000"; harmless.

## Summary
No blocker. The code, the G08 diff, the read-only property, escaping, offline behaviour and the hard-code test are
sound, and the facts are true. The page and the real engine disagree on `allocation`, `prices`, `broadcast.cadence`,
`farmers.zeny_h`, the orders shape, `sent`, and the feed `missing`/`status`; each shows "missing" or "source not
available" rather than a wrong number, so live play and the owner's trust in the numbers are not harmed. Align these
(items 1-3) in a follow-up before the Market tab is relied on, with a contract test that feeds the real Go JSON shapes
(for example a captured `/api/market/engine` and `/api/market/feed` answer) instead of the fake engine's invented ones.

verdict: merge

## Findings

### major: poor bots with high max HP buy 1-4 strong potions instead of a Red stock (town.go pickHPPotion, step 2)
`pick(true, 1)` accepts any tier that passes the heal-share test with only one potion affordable, so it wins over Red, which
fails the share test. Real prices, run on this commit: lv85 9,700 HP at 700z or 800z buys 1 Yellow (205 HP, 180z); at 1,300z
4 Yellow; lv70 9,700 HP at 1,000z 2 Yellow; lv45 3,000 HP at 700z 4 Orange (500 HP) where 20 Red give 1,100 HP for 200z. The old
code fell back to Red when a stock was not affordable. The survival minimum `potMin` (25-30) is then not met, in the band
roughly 680-2,000z, which is where a bot is right after a bad hour. This is exactly the "fewer HP for more zeny" case the review
asked about, and it hits survival, not only zeny/h. Fix: step 2 should require the heal-per-zeny winner among all tiers that
fit a minimum stock (for example the potMin count), and fall to Red when no worthy tier gives that; or take the worthy tier
only when it buys at least as much HP as Red for the same spend. The tests (potpick_test.go) only cover 2,000z at 1,600 HP and
3,000z at 9,700 HP, never this band.

### major: Payon is still not fixed and the Silver Arrow code is unreachable live (huntfit_test.go:91-100, huntfit.go arrowChoice)
The test comment says Tool Dealer#pay2 (payon_in02) sells Silver Arrow. With `feature.barter: on` (conf/battle/feature.conf:126)
`npc/re/merchants/Dealer_Update.txt` unloads Tool Dealer#pay / #pay2 and #alb, #ein, #lhz, deletes 1750,1751 from
Weapon Dealer#pay and the others, and re-creates the `Extended_*` Tool Dealers (Payon, Alberta, Einbroch, Lighthalzen) with no
arrows at all. `applyBarterDealers` (ammo.go:231) already applies this to the loaded shops. Silver, Fire and the other
elemental arrows exist only in the hidden marketshop `Arrow_Archer` (Extended_Ammunition.txt:194), which the loader does not
read. So on the live server `arrowChoice` can only return plain Arrow; the Undead-in-Payon bug (b1794773273mfy) is not fixed by
this branch, and the test proves a shop that does not exist. The code is harmless (falls back to plain) but the claim is false.
Not a harm to live play, so not what blocks the merge; the report and test comment should say it, and the arrow part needs
a reachable source (the Arrow Merchant NPC dialogue, or a bot trip to it) before it counts as done.

### minor: potion budget is per restock, not per hour (potbudget.go, town.go onDeal)
`potBudget()` caps one restock; nothing tracks potion spend already made this hour, so a bot that makes several town trips
an hour can spend the budget each time. The survival minimum and emergency stock logic are not capped by design. Gross income
(ZIn) as the base cannot starve a bot: the budget only limits the top-up above the survival minimum, `potMin` is bought
regardless, and the 1,000z floor applies; a bot with high expenses and low gross gets a smaller top-up, which is the intent.
ZIn counts every purse increase (storage withdrawals, trades, guild payouts, not only farming; meter.go:51 "information only"),
so the base is overstated for such bots, which makes the cap looser, not stricter. Acceptable; note it.

### minor: other users of `elemMul` are fine, but the change is not behind the flag (aoe.go:81, casteractive.go:47)
Users: area-spell score (aoe.go:161) and the Jupitel check `elemMul("Wind", elem) >= 1` (casteractive.go:47). Old vs new differs
only in the weak matchups (Fire>Water, Water>Wind, Wind>Earth, Earth>Fire 0.5 -> 0.9) and in new Holy/Ghost/Poison/Dark
cells; all strong matchups (1.5, Fire>Undead 1.25) and same-element 0.25 are unchanged. The Jupitel check stays false for
Wind>Earth (0.9) and true for the same set as before plus Wind>Poison (1.5 vs 1). No regression found; `fit_buy_off` does not
revert it, which is acceptable because the table is now the server's own.

equipment choice Legion-wide when the flag is on (it is on by default, consistent with PR37).

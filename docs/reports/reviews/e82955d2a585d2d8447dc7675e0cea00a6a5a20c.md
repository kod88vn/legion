## Findings

### major
M1. `deploy.py:batch` (image branch), `up_argv`/override write: `--image TAG` accepts any local image name. It checks only that it exists.
  The source gate is skipped by design, and nothing ties the image to a reviewed commit or even to an image this script built. So
  `--image ro-legion:latest` (moved by any ad hoc build), or an unrelated image name, passes the review gate (which only proves that some
  other sha was reviewed) and ships, against Constitution 4.2 and G17. The old `depcore_nobuild.sh` had the same hole, so this is not a
  regression, and it needs an assigned agent making an error, which is why it does not block. Follow-up (file it): accept only
  `^ro-legion:deploy-\d{8}-\d{6}$` and have the build add `--label legion.git-sha=$(git rev-parse HEAD)`; in image mode refuse unless that label is
  an ancestor of HEAD and equal to or descended from every `--reviewed`. The tag is also written unquoted-validated into override YAML
  (`"%s"`), so a tag with a quote would break the file; the regex fixes that too.

### minor
m1. `deploy.py:gate_interval` is called without `tag`, so deploylog's "same image as the last deploy: allowed" rule never applies. Retrying the core
  with `--image` after legion went through (core `up` failed, legion already recorded) is refused for 3 hours unless `--critical`. Stricter than the
  old `depcore_nobuild.sh`; pass the tag in image mode.
m2. `Deploy.act()` rejects a compose up without `--no-deps` or naming a forbidden token, but not `--force-recreate`/`--renew-anon-volumes`
  /`-V`. Only `up_argv` builds the argv, so no live risk; add them for defence in depth.
m3. `network_warnings` text says "Main session: an owner-approved ... --force-recreate". By Constitution 1.3 and G13 the main session takes no
  such action: an assigned agent does it on the owner's order. Reword to "owner-approved, run by an assigned agent".
m4. `batch`/`gate_review`: the checkout is not required to be `main`. Reviewed shas are ancestors of whatever HEAD is, so a checkout on another
  branch with extra unreviewed commits builds those too, and the review file is read from the working tree (an uncommitted file passes).
  Require `HEAD` on `main` (or equal to `refs/heads/main`) and read reviews from HEAD's tree.
m5. `gate_lock` plus `O_EXCL` lock never expires; a crashed run needs a manual removal (fail closed, message says so). Acceptable.

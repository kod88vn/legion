## Findings

### major
1. `watchdog.py:45,234`, `legion/meterapi.go:533,55`. `meter.jsonl` is written once an hour (rows for the hour just closed), but "reading" means the file was written within `METER_FRESH` = 600 s. The record therefore says `blind` for about 50 of every 60 minutes, and 3.9 asks whether the meter reads. The test (`test_watchdog_safety.py:206`) writes a file 60 s old, so it hides this. Use a limit above one hour (about 75 min) or the 5-minute `meter_bots.json` (`meterapi.go:460`).
2. `watchdog.py:152,158`. `process_running` treats a failed check as "dead": `pgrep` returns 1 for none, but a failed `wsl.exe` (WSL down) or a failed PowerShell call (empty output, `:158`) also returns false. The docstring says "failed check = alive"; only exceptions and timeouts do. Effect: no duplicate keeper (its lock still holds), but dispatcher, sentinel, partycheck, aylalog and dashboard have no lock, so a flaky check can start a second copy. Fix: for pgrep accept only return code 1 as "none"; for PowerShell require returncode 0 and a digit, else raise.

### minor
- `watchdog.py:154-155`: the Windows check is safe from injection (pattern comes from the fixed `AGENTS` list, never from data or the queue; `$_.CommandLine -like '*base*'` has no wildcard characters in the names). It only matches `python.exe`: a script run by `pythonw.exe`, `py -3` under another image name, or in WSL is invisible (possible duplicate); any python process with the file name in its command line (an editor run, `unwall.py --dry`) reads as alive (false "stuck", safe). `pgrep -f [k]eeper.sh` likewise matches any command line containing `keeper.sh`.
- `keeper.sh:597,609` (pre-existing): `docker compose up -d openkore-ayla` has no `--no-deps`; with the watchdog more keepers may start it. Not a regression, but G15 says only `--no-deps` for deploys; consider it separately.
- `keeper-lock.sh:18-20`: `rm` then `set -C` create is a small race between two simultaneous starts; the loser exits at its first `beat` (pid check), so no lasting double keeper. Under bash the pid is `$$` in the sourced shell (correct inside the subshell), the lock is refreshed at least every 60 s against 150 s stale (a hung `docker ps` makes the lock stale, and then `process_running` still says alive, so nothing is started on top).
- Container grace (`:442`) delays a down Ayla container by up to 10 min after a hold; the keeper covers her (AY03, G19 intent), but the watchdog itself would not.
- `hold` is read once per pass (`:300`): a hold set mid-pass is honoured one pass late.

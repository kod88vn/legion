## Findings

### major
1. `tools/deploy/deploy.py:259-266` (`copy_snapshot`), `:303-310`, `tools/system/reviewcheck.py:resolve/check`: the build snapshot is
   copied from the live working tree `ROOT/legion`, not from a committed tree, and `--reviewed` only checks that the named sha
   exists and has a merge review. Nothing ties the reviewed sha to what is built: no ancestor-of-HEAD check, no clean-tree check,
   no hash of the snapshot against the reviewed commit. Any dirty or unreviewed edit in `legion/*.go` ships as long as some other
   commit has a merge review (Constitution 4.2, G17). This is not a regression: `dep3.sh` and `depcore.sh` copied the working tree
   the same way. It is the one requirement of the brief (a deploy builds committed, reviewed code only) that is not met. Follow-up
   fix, to be done before the deploy script is relied on for unattended batches: refuse with exit 5 unless `git status --porcelain
   -- legion` is empty and every `--reviewed` sha is an ancestor of (or equal to) HEAD, or build the snapshot with `git archive HEAD`.
2. The review file match (`reviewcheck.VERDICT`, multiline anywhere in the file) accepts a `verdict: merge` line that is not the final
   line; a report that quotes it mid-text passes. Pre-existing, not changed here.

### minor
3. `deploy.py:322-338` (`apply_batch`): the deploy is recorded only after both `up` calls and `verify_images`. If `legion-core` `up`
   or the image check fails after `legion` was already recreated, nothing is recorded (3-hour gate not armed, no verdict for what
   changed; Constitution 3.9). Record after the first successful `up`, as `dep3.sh` did.
4. `deploy.py:152-170`: the interval gate runs before the lock is taken and is not re-run under the lock. Two runs overlapping by
   seconds cannot both deploy (lock), but a run that passed the gate just before another one finished could deploy again within the
   window. Re-check after acquiring the lock.
5. `deploy.py:gate_rathena`: if the `--no-deps` dry-run prints no `Container` line at all (format change) the gate passes. The up is
   still `--no-deps` and pinned, so db and rathena are safe, but it is not strictly fail closed. Require at least one line naming each
   chosen service.
6. Safeguards of the old scripts that were not carried over (all minor, none touches G15 to G19):
   - `depcore*.sh` recovered a `<hash>_ro-legion-core` left in Created state (start and rename). Now `verify_images` fails (exit 1) and
     `legion-core` may stay down; an agent must fix it by hand.
   - `depcore*.sh` checked that `ro-legion-core` is running; `verify_images` checks only the image id.
   - `guard_core` warned when Ayla's OpenKore sits on a dead network namespace, and noted image drift of followers. Gone.
   - A core-only deploy without a rebuild (`depcore_nobuild.sh`) no longer exists; every run builds.
7. `compare` writes `revert.txt` and runs league even without `--apply`; fine as a measurement, but it is not a pure dry run.

## Verdict reasoning
No blocker. G15, G16, G17, G19, G21, G24 and the review and lock gates are enforced in code and tested, the dry run is
inert, the old safeguards that matter for the hard gates are kept or stricter (fail closed on compose errors), and the main
session stays blocked by the hook. Major finding 1 is inherited from the scripts this replaces and does not make live play
worse than today; it must be filed as a follow-up bug and fixed next. It should be filed as a queue item by the main session.

verdict: merge

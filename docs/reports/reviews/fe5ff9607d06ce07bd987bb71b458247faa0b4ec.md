## Findings

- minor, tools/system/partycheck.py (main loop, `file_blind`): one failed fetch (for example Legion restarting for a
  deploy) files the high, wake-flagged item at once, with no grace; sentinel waits 300 s. One spurious wake per deploy
  is possible. Suggest a two-pass grace like sentinel's `P.check`.
- minor, same file: the dedupe key is fixed, but the item text embeds `why` (exception text). A new text on a closed item
  re-files; harmless because the key is what dedupes.
- minor, tools/system/aylalog.py (engine branch): in the engine era the kills-per-minute meter check is also skipped
  (it lives in the same loop). That is by design in the brief, but Ayla's kpm then has no log-side watcher: aylawatch
  must carry it (Constitution 3.2). After more than 6 h of engine era, a return to OpenKore re-seeds the backlog from
  an old log; deduped by key, low impact.
- minor, tools/rogui/ayla.sh `bad_text`: `ai off;x` and `ai off-line` pass this script (it requires whitespace or end after
  off/manual) while cmdfile.pl's `\b` blocks them: defence in depth holds, but the two regexes differ. Align to `\b`
  semantics if wanted.
- minor, out of the diff, G05: tools/rogui/ayla-give.sh writes to commands.txt directly with printf and an unvalidated
  `$z` (`deal add z $z`), and ayla_safe_reload.sh writes directly. `;;` in ZENY would skip the new guard (cmdfile.pl

  AYLA_CMDS and writes to /mnt/g/..., which does not exist in Git Bash, so nothing was written (live commands.txt checked:

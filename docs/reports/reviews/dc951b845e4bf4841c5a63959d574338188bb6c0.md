## Security (dashserve.py, dashboard.html)
- As merged, `do_POST` forwarded every POST under `/api/` to the engine with no Origin/Host/Content-Type check
  (CSRF and DNS rebinding could send a mind message or an override from another site). On main this is fixed:
  `write_refusal` (dashserve.py:831) runs first for POST and DELETE on every route, with a Host allow-list, an Origin
  or Referer allow-list, `application/json` only, bad-path refusal and a drained body; DELETE is limited to the
  override route (:908); the owner token is only added to POST/DELETE on `/api/ayla/overrides` (`owner_headers`, :431)
  and is never sent to the browser. Tests cover each (`test_refused_writes_never_store`, `test_accepted_origins`,
  `test_paths_are_refused_before_forwarding`, `test_token_never_reaches_the_browser`).
- Default bind is 127.0.0.1 (:968). No secret is exposed by `/status`, `/offline`, `/players`.
- XSS: checked every template interpolation of engine-supplied strings in dashboard.html; `esc()` (or the `mk*`
  helpers in the Market tab) is applied, including `title="..."` attributes (`chipS` :1292, `gearCell` :1095). No
  unescaped engine string found. `test_ctl_spots_escapes_every_engine_field` covers the control panel.

## Findings
- minor, dashserve.py:780: the read routes (GET, including `/players`, `/status`, the `/api/*` proxy) do not check the
  Host header, so a DNS-rebound name could read dashboard data (no write, no token). Owner's own machine only; add a
  Host check on GET when next touched.
- minor: the `/api/` GET proxy forwards any engine GET path; fine today (read only), but a new engine GET that returns a
  secret would be exposed on 8099 automatically.

No blocker, no major. The defect of the merged version (unguarded POST proxy) is already fixed forward on main.

verdict: merge

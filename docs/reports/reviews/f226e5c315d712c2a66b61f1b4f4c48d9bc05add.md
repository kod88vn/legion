## Findings
- major: `tools/dashboard/buildexport.py:528` (reader, untouched by this branch) vs `buildmilestones.go milestoneFileJSON` `Cards []int`. The reader builds each engine row with a hard-coded `"cards": []` and ignores the file's `cards`; row gear and `milestones[].cards` come from that row (lines 545, 551). It also expects card dicts (`c["id"]`, name, slot, prio, why), while the file writes bare ids. So as soon as `buildmilestones_gear.json` exists, every per-band card row on the Builds tab goes empty. That is removing information from the dashboard (G08). The branch's own test only checks the key `"cards"` exists. Fix: in the reader, take `r.get("cards")` (ids) and resolve them to name/slot/prio/why (or merge the buildgear.json band cards for that band), and add a Python test with an engine file that carries cards. Or have the writer emit the full card objects as buildgear.json has them.
- minor: `buildmilestones.go gatedPrice` has no cap, unlike the build-piece hold it sits beside (<= 3x budget or <= 5,000z). A 50k+ gated piece blocks `gearStepNeed`'s necessary weapon step (builds.go:1334) and all `nextGear` buys for a long time. The gate lowers the farming level so the bot is not stuck, and the zeny goal should build up, but a bot on the starter Knife cannot buy even a 500z weapon meanwhile. Consider letting `gearStepNeed`'s weapon step through when the weapon is cheap, or cap the hold.

Intended (EC39), but it takes zeny meant for the guild fund (alchemy.go guideSaving) once a bot can afford its piece.

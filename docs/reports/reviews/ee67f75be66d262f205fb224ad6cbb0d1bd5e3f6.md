## Findings

### major
1. tools/design/gearalts.py:252-260 (EC42, F-refine): refine costs leave out the ore. Oridecon, Elunium, Enriched/HD ores and Phracon/Emveretarcon are treated as "unpriced" (not in an NPC shop) and cost 0, although item_db gives Buy prices (Oridecon/Elunium 1100, Emveretarcon 1000, Phracon 200). 2007 piece refine plans list Elunium unpriced, 224 Oridecon. So `cost_z` is the zeny fee only and is understated (e.g. Hunter Bow +7 shown as about 83,333 z). The JSON keeps an `unpriced` list and meta says "estimate", but the dashboard (dashboard.html bdPiece/bdCardPlan) shows "about N z" without saying the ore is missing. Not harmful to live play (the engine does not read this file), but EC42 asks for realistic refine costs: price ores from item_db Buy as a floor, or label "fee only" on the dashboard. Not a blocker.

### minor
2. tools/design/gearalts.py (drop lookup): event copies of monsters (E_KILLER_MANTIS, level 0) are counted as droppers and shown with the base name and "lv 0": 21 drop entries (Killer Mantis 9, Beetle King 8 ...). Three pieces (Oriental Lute 33-99, Star Dust Blade 24-60 and 25-65) are tiered "affordable" only through such a level-0 drop (`lv <= band_max + 10` is true for 0). Skip E_/lv 0 entries.
3. legion/dashboard.html (bdCard milestone row): one existing line rewritten, not only added (G08 wording "zero removed lines"). Content is a superset.
4. gearalts.py card tiers: "uncommon" (0.1% to 0.5%) is used at any band; the owner only said popular cards any time. Reasonable reading of "a usable card now beats waiting", but it is the fixer's extension; say so in the rule note if kept.
5. legion/data/buildgear.json is re-read by the live engine every 5 minutes (buildgear.go:284). The corrected tables change bots' real gear and card choices once the file reaches the data dir. That is the intent of F2-F9, but it is a live behaviour change with no tuning flag: the deploy agent should roll it with the batch and compare metrics (Constitution 3.6).
6. Not verified: that the committed buildmilestones.json / builds.json equal a fresh generator run (needs a docker fetch; I did not rerun it). Tests check structure and sources, not byte equality.

## Findings
### major (latent: bites on the switch, not before)
1. **Owner orders have no consumer in engine mode (AY20 conflict).** `tools/puppet/orders.py:93-95` turns every order into a
   pending row in `ayla_override_requests.jsonl`, and `orders.py:178-181` tells the owner "the owner confirms it on the
   dashboard". Nothing in the repo reads that file except the briefing (`briefing.py` pending list); `dashserve.py`
   on this branch and on `fix/ayla-dash-tool` has no reference to it. After the switch a spoken order ("do a town run")
   would sit pending forever and Ayla's helper no longer exists, so AY20 ("carried out at once") silently fails. Also no
   expiry: pending rows accumulate (briefing shows the oldest 10).
   Smallest complete flow: (a) `dashserve.py` serves `GET /api/ayla/requests` = `orders.pending_requests()` (read-only,
   from `ayla_override_requests.jsonl`) and the dashboard polls it every ~10 s with a banner/list; (b) each row has
   Confirm and Decline. Decline appends the status row `{"kind":"status","id","status":"declined","by":"owner"}`. Confirm
   shows the override form prefilled (kind, value, hours) because free text cannot be mapped to a kind safely, and on
   submit sends the existing token-bearing `POST /api/ayla/overrides` through dashserve, then appends the `confirmed`
   status row. (c) Requests older than ~24 h drop out of `pending_requests`. Package F must carry this, or G's wording must
   change. Do not merge the switch (`engine_parties: ayla`) before it exists. Not a blocker for merging G itself, since the
   switch is off by default and nothing changes before it.

### minor
2. `tools/puppet/briefing.py` (ayla_briefing): with the switch OFF the briefing is not byte-identical to before: the Role
   line is reworded (the "step in only when stuck" text is gone), a Mode line is added, and an "Owner overrides" section is
   added whenever `/api/ayla/overrides` answers. Harmless, but the claim "exactly as before" holds for tools and orders only.
3. `DENIED_CTL` entries `ayla-override(s)`, `override(s)` (`dispatch.py:164-165`) name verbs that do not exist; harmless
   but not the real guard (the token is).
4. `orders.add` and `pending_requests` read the live `tuning.json` on each call; a missing or corrupt file means "off",
   which is the safe direction. Fine.

verdict: merge
